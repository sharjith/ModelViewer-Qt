Introduction to simulation results

A simulation - a finite-element stress analysis, a heat-transfer run, a flow calculation - ends with a result file: the mesh the solver worked on, and for each point or cell of it one or more fields (stress, displacement, temperature, velocity, pressure ...), usually for several steps (load steps, vibration modes, moments in time). ModelViewer reads such a file and shows the model coloured by a field. This chapter explains the idea and the vocabulary; the following chapters go through the features one at a time.

A viewer, not a solver

The boundary matters, because it explains both the strengths and the limits. ModelViewer is read-only with respect to the physics: it never changes a value, never runs a calculation of its own other than the display arithmetic described below (derived stress values, unit conversion, averaging), and has no solver, mesher or expression language. In exchange it stays small and fast, and every result gets the same presentation tools as any model: selection, sections, measurement, annotation, report export and the rest of the viewport.

What you see: the boundary surface

A solid result has millions of cells inside, but you look at a solid from outside. ModelViewer therefore extracts the boundary surface - the faces that belong to exactly one cell - and draws that, coloured by the chosen field. The interior is not lost: sections, iso-surfaces, streamlines and volume rendering (chapter 6) reach into it, and probes and charts read values from it. Results that already are surfaces (shell models made of triangles or quadrilaterals) are drawn as they are.

  • Supported cell types: tetrahedra, hexahedra, wedges, pyramids, their quadratic forms (drawn through their corner nodes) and polyhedra with explicit faces. Triangles and quadrilaterals are shells.
  • Cell types that have no surface to draw - polygons, triangle strips and single vertices of the legacy VTK format, and the 1-D beams of a network - are read but not displayed; this is expected.
  • The displayed surface is an ordinary mesh in the scene, so it can be selected, hidden, transformed, measured and annotated like any other.

Vocabulary

Field
One kind of value over the model: a scalar (temperature), a vector (displacement, velocity - three components) or a tensor (stress - six components).
Node data and cell data
A node field has one value per mesh point and is drawn smoothly interpolated. A cell field has one value per element and is drawn in one flat colour per element (marked [cells] in the field list).
Step
One state of the result: a load increment, a time step, or a vibration mode. A result with several steps shows a timeline.
Component
One of the parts of a vector or tensor (X, Y, Z ...) or its magnitude.
Range
The values that the colour scale spans, from its minimum colour to its maximum colour.
Derived field
A value computed from another one at load time - for stress files, von Mises stress, Tresca stress, the three principal stresses and the maximum shear.

Supported formats

The readers are ModelViewer's own; there is no dependency on VTK or ParaView. Which formats appear in the Open dialog depends on the libraries your build includes.

FormatExtensionsNotes
VTK.vtu, .vtkThe common interchange format. XML files (inline, appended raw and compressed data) and legacy files (ASCII and binary). Polyhedra are supported. FreeCAD's FEM export writes .vtu.
CalculiX.frdThe result file CalculiX writes (and FreeCAD FEM keeps). Displacements, stresses and strains; von Mises, principal stresses and maximum shear are derived while loading. Values are in the solver's own units.
Exodus II.e .exo .ex2 .gCommon for MOOSE and Sierra results. Needs a build with NetCDF. Node and element variables, many steps.
CGNS.cgnsUnstructured and structured zones. Needs a build with the CGNS library. Vertex and cell-centre solutions; boundary-condition sections are skipped.
VTKHDF.vtkhdfThe HDF5-based VTK format as ParaView writes it, including time steps. Unstructured grids, poly data and image data are read; composite files are not supported yet. Needs HDF5.
MED.medCode_Aster and Salome results (MED 3 and later). Needs HDF5. Older Code_Aster 2.x-layout files must be converted (Salome's medimport).
OpenFOAM.foamOpen the (empty) .foam file in the case folder. The case's time directories become the steps. Polyhedral meshes are supported.
Note

Help → About lists the optional libraries of your build. If an extension is missing from the Open dialog's filter, that build was made without the matching library, and the format will not open.

The workflow in short

  1. Run your analysis in the solver of your choice and keep the result file.
  2. Open it in ModelViewer (File → Open...), pick a field, check the units.
  3. Look: rotate, section, step through time, probe values, chart them, compare with another run.
  4. Present: add annotations or measurements, capture views, export a PDF report or an image, or save a .mvf session that contains the result.
