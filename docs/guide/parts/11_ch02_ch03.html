Opening a result

Two ways to open

CommandWhat happens
File → Open... (or Ctrl+O, or drag the file onto the window)The result opens in a document of its own. This is the normal way and the one to use first.
Visualization → Simulation Results → Add Result to This Document... (also Add Result... in the tab)The result is added to the current document, next to whatever is there - a CAD model, another result. Use it to compare two results (chapter 8) or to see a result together with a plot (chapter 18).

Both accept the same files. The file filter offers All Simulation Results and one entry per format. An OpenFOAM case opens through the empty .foam file in the case folder.

While it loads

Reading, decompressing, tessellating and extracting the boundary surface run in the background, with a progress bar and a Cancel button, so the program stays usable. Only one result loads at a time; starting a second while one is loading gives a message. Large text formats (ASCII .frd or .vtk) are much slower to read than the binary HDF5 and NetCDF based ones, which is a property of the formats, not of the program.

The Simulation Results tab

Once a result is loaded, the dock at the bottom left switches to the Simulation Results tab. It holds nearly everything in this part of the guide, and its controls are inactive until a result is selected. From the top:

  • Result: which result of the document the controls act on, with a button that removes the selected result from the document (this can be undone), and an info line with the file name and the counts - nodes, cells and surface triangles.
  • Model unit and Model size: the length unit of the geometry (metres, centimetres, millimetres, inches, feet; when the file does not say, Not specified (assumed mm)) and the size of the model in it.
  • Field, Component, Quantity and Values are in: what to colour by, and its unit (chapter 3).
  • Range, Colormap, Contours, the deformation and marker options, and the groups for sections, iso-surfaces, streamlines, volume, arrows and ellipsoids (chapters 3, 4 and 6).
  • Charts: the buttons for plotting over a line or over time and for the distribution (chapter 7), and the Compare controls (chapter 8).

Results without fields or without volume

  • A file that contains only geometry shows the geometry, and the tab says so: there are no values to colour by.
  • A shell result (triangles and quadrilaterals only) has no volume. Everything that needs a volume - sections that reveal the inside, iso-surfaces, streamlines, volume rendering - reports that there is nothing to cut or trace. Colours, deformation, probes and charts all work.
  • A result without a displacement field cannot be shown deformed; the option explains this.
Tip

If you are unsure what a file contains, open it and look at the Field list and the info line first: they show every field the reader found, which steps exist, and how many nodes and cells it has. For a first try, sample-models/Simulation/FEM_box_static_stress.vtu is small and opens coloured by von Mises stress.

Fields, colours and units

Choosing the field

Field lists everything the file contains, plus the derived values. A vector field offers Component choices - its components and its magnitude; the six components of a stress tensor are summarised by the derived scalars described below. Fields marked [cells] are element data.

Derived stress values

When a file contains a symmetric stress tensor (six components, in the order XX, YY, ZZ, XY, YZ, ZX), ModelViewer derives the quantities engineers usually want and adds them to the field list as ordinary scalars: von Mises stress, Tresca stress, the three principal stresses and the maximum shear. They are computed per node (or cell) from the tensor as each step is loaded; they inherit the unit of the stress and are not stored in a saved session, because they can always be recomputed. CalculiX .frd files are the typical source; FreeCAD's .vtu export already contains some of them.

Node data and cell data

A node field has a value at every mesh point and is interpolated smoothly over each face, so a coarse mesh still shows smooth colour. A cell field has one value per element: each element is drawn in a single flat colour, which is the honest picture of element-wise data (for example an element quality, or most OpenFOAM fields) but looks blocky.

Average cell data to nodes (enabled while a cell field is shown) draws the field smoothly instead: each node takes the average of the elements around it, weighted by their size, so a small element counts for less than a large one. It is a display choice - the data itself is not altered - and it is also what charts, volume rendering and iso-surfaces use for a cell field. Leave it off for labels such as a material or group number, whose regions are identifiers, not quantities.

The colour scale

Range

Range settingThe scale spans ...
Automatic (all steps)the smallest and largest value of the field over all steps. This is the default: it keeps the frames of an animation comparable, because a colour means the same value in every step.
Automatic (this step)the smallest and largest value of the current step only. Every frame uses its full colour range, which shows structure well but makes frames incomparable.
Customa Minimum and Maximum that you type, in the display unit. Values outside are shown in the end colours. Use it to compare runs or to enlarge an interesting band.

Colormap, bands and legend

Colormap chooses the ramp: sequential ramps such as the rainbow, and a diverging blue-white-red ramp that suits quantities with a meaningful zero (a displacement component, a signed stress). Contours turns the smooth gradient into a set of discrete bands (or back); with bands, the colour boundaries lie exactly at equal values and inside the triangles, not at mesh edges. The legend beside the model shows the scale, its unit and the step; result surfaces are drawn unlit, so lighting never alters the colours.

Min / max markers and the hover readout

Mark minimum and maximum labels the lowest and highest values on the visible surface (the true extremes of a solid may lie inside; sections reveal them). Independently, hovering over the model with the mouse shows the value of the shown field at the cursor, with its unit. The hover works whenever a result is selected, except while two results are being compared (chapter 8).

Units

A wrong unit on a stress or a temperature is exactly the error a presentation tool must not make, so units are explicit and never guessed silently.

  • Every field has a quantity (stress, displacement, temperature, velocity, pressure ...) and two units: the one in the file and the one displayed.
  • Quantity and Values are in let you state them. When the file carries a hint, ModelViewer uses it (OpenFOAM states its units through the dimensions of each field: temperature in K, velocity in m/s, a stress tensor in Pa; a kinematic pressure has no unit); when it does not, you choose, and the panel marks the unit as assumed until you confirm it.
  • Conversions are more than scale factors: temperature moves between kelvin, degrees Celsius and degrees Fahrenheit, which is an offset as well as a factor.
  • The legend, the hover readout, the markers, the charts and the report all use the displayed unit.
  • Derived fields inherit the unit of the field they come from.
Caution

Solvers write what you gave them. A CalculiX run with a model in millimetres and Young's modulus in MPa reports stress in MPa and displacements in mm, but the file does not say so - ModelViewer shows plain numbers until you choose the units (the sample FEM_box_static.frd is in mm and MPa; its .vtu sibling shows Pa). Always check Values are in against the units of your analysis.
