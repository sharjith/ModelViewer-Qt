# Raster light-intensity synchronization

24 October 2026, `feature/JT-importer`. Owner accepted the focused ADS/PBR retest after rebuilding and installing. This shared-renderer correction was discovered during [C2ad border qualification](JT_BORDER_BATCH_VALIDATION.md).

## Evidence and correction

The affected original JT, independent reference and application exports had identical resident RGBA pixels at all seven mip levels, matching sampler parameters, positions, normals, UVs and indices. Removing/adding neutral white vertex attributes appeared to affect brightness, but did not establish a vertex-colour defect. The red inner cube also differed: screenshot samples measured red 119 versus 148.

Opt-in draw evidence in ignored `out/jt-research/c2ad-reference-vertex-diagnostics.jsonl` showed matching material scalars but different GPU light values: ambient/diffuse/specular 0.20/0.80/0.50 versus 0.12/1.00/1.00. These correspond to saved render-setting defaults and initial/default-light synchronization respectively. The deferred settings path writes uniforms outside the regular viewport drawing path; intensities were not refreshed by `setCommonUniforms`, although position was. The observed stale GPU state is established; the source analysis does not claim exhaustive reproduction of every context/timing interleaving.

`ViewportWidget::setCommonUniforms` now uploads the viewport's stored ambient, diffuse and specular values to the drawing shader alongside light position. It preserves configured intensities, light colours, source materials, vertex attributes, image pixels and path-tracer light assembly. Existing opt-in diagnostics additionally record the stored vectors so actual GPU values can be checked against their source.

## Owner acceptance and limits

The owner reported successful installation and that all five focused documents look the same in both ADS and PBR: affected JT, independent reference, exported GLB, exported glTF and reference with neutral white vertex colours. The post-fix evidence `out/jt-research/c2ad-light-uniform-retest.jsonl` contains five populated viewports; each latest draw's ambient/diffuse/specular uniforms equal its stored vectors, and all use configured diffuse strength 0.8. This supersedes the vertex-colour hypothesis. No native suite or separate CPU/OptiX execution is claimed.

To regenerate draw evidence after the owner builds and installs, set `MODELVIEWER_APPEARANCE_DIAGNOSTICS` to an absolute filename beneath ignored `out/jt-research/`, then launch those five original controls together using the installed viewer. Compare matching Y-Up isometric views in ADS and PBR. Controls are regenerated by the command in the C2ad record; representative application exports require owner interaction. Diagnostic variants only add/remove neutral `COLOR_0` data and remain local under `out/`.

This correction used original project source, owner screenshots and local draw/export evidence only. No new third-party implementation, model, vendor software/SDK, external reference, download or licence interpretation was used. Samples, image measurements and logs remain ignored; this statement records method and limits, not legal clearance.
